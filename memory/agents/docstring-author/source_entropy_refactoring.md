巨大モジュールを凝集性に沿って分割するときは、関数・クラスだけでなく、その契約を説明する
docstring と理由を説明するコメントも実装の所有モジュールへ移す。元の import 経路を維持する
ファサードには、再公開する識別子の個別説明を複製せず、互換ファサードであることだけを書く。

監査では、移動先のモジュール docstring が実際の変更理由と一致すること、実装に密着したコメントが
ファサードへ取り残されていないこと、ファサードが分岐や Blender データ変更を持たないことを確認する。
説明が既に正確なら、分割した事実だけを理由に加筆しない。
